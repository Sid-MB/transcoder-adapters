# Legend — `transcoder_finetune_before_after.png` (FVU) & `transcoder_finetune_l0_before_after.png` (L0)

**What these figures show.** Both compare, per fine-tuned layer (0, 24, 25), how a GemmaScope transcoder behaves before vs. after we re-fine-tuned it — against a fixed reference. A GemmaScope transcoder is a pretrained sparse module that approximates a `gemma-2-2b` MLP layer (encoder → JumpReLU → decoder). Each layer has **three bars**:

| bar | transcoder weights | input hidden states (`x`) |
|---|---|---|
| **instruct, before FT** (red) | original GemmaScope | **instruct** model (`gemma-2-2b-it`) |
| **instruct, after FT** (orange) | **fine-tuned** | **instruct** model |
| **base (target level)** (blue) | **original** GemmaScope | **base** model (`gemma-2-2b`) |

**What "base" means.** The blue bar is the **reference / target**: the *original* transcoder running on the *base* model's own hidden states — i.e. the distribution GemmaScope was actually trained on, its **native operating point** ("how it's supposed to behave"). It is NOT a fine-tuned or instruct measurement. The whole goal of the fine-tune was to make the transcoder behave on **instruct** inputs the way it natively does on **base** inputs, so we want the orange bar (after FT) to move toward the blue bar.

**Reading each figure.**
- **FVU** (`transcoder_finetune_before_after.png`): FVU = fraction of variance unexplained = how much of the true MLP output the transcoder fails to reconstruct (lower = better). Blue is the reconstruction-quality floor; success = orange drops down to blue. Result: L0 0.108 → 0.075 (base 0.082, fully recovered), L24 0.281 → 0.221 (base 0.21, recovered), L25 0.317 → 0.212 (base 0.15, most of the way).
- **L0 / sparsity** (`transcoder_finetune_l0_before_after.png`): L0 = active features per token (the sparsity operating point). Success = orange sits *at* blue. Result: L0 81 vs base 80 (matched); L24 67 vs 56 and L25 81 vs 65 (overshoot). The overshoot is expected — the fine-tune had **no sparsity penalty** and **froze the JumpReLU threshold**, so the shifted `W_enc`/`b_enc` push more features over the fixed threshold. (Adding an L1/L0 term or training the threshold would pin L0.)

**Naming caveat.** "base" here means the **base model** (`google/gemma-2-2b`) as the *source of hidden states* — nothing to do with the trained transcoder *adapters* (the project's bridging modules). All three bars use **GemmaScope** transcoders; they differ only in fine-tuned-or-not and which model's activations feed them.

Data sources: blue bars = Experiment 1 base-source run (job 16113808, `data/exp1_all_layers_results.json`); red/orange = fine-tune before/after eval on held-out instruct tokens (job 16114293, `data/finetune_report.json`).
